PART 1: UNDERSTANDING THE RAW DATA
================================================

We have 4 data sources:

1. RATINGS.CSV (210,038 records)
   ---------------------------------
   Structure: user_id, movie_id, rating, timestamp
   
   Example rows:
   user_id | movie_id                               | rating | timestamp
   --------|----------------------------------------|--------|-------------------------
   70106   | die+hard+1988                          | 9      | 2025-12-27T21:14:45
   42281   | lock_+stock+and+two+smoking+barrels+1998| 8     | 2025-12-27T22:57:25

   Key Points:
   - Users rate movies 1-10 stars
   - movie_id is the movie title + year (URL-encoded format: "+" for spaces)
   - Each user rates multiple movies
   - This is our PRIMARY signal for what users like
   

2. WATCHES.CSV (300,484 records)
   ---------------------------------
   Structure: user_id, movie_id, minutes_watched
   
   Example rows:
   user_id | movie_id              | minutes_watched
   --------|-----------------------|----------------
   53873   | before+sunrise+1995   | 107
   53873   | death+proof+2007      | 115
   53873   | skyfall+2012          | 50
   
   Key Points:
   - Tracks HOW LONG users watched each movie
   - Some users watch full movie (~120 min), some quit early
   - Used for popularity calculations (popular movies = watched more)
   

3. USERS METADATA (JSON - ~100k users)
   ---------------------------------
   Structure: Dictionary with user_id as key
   
   Example:
   {

     }
   }
   
   Key Points:
   - FREE TEXT fields for likes/dislikes (this is our COLD-START solution!)
   - Users mention specific movies they like (e.g., "The Godfather")
   - We parse this text to extract preferences for new users
   

4. MOVIES METADATA (JSON - ~20k movies)

PART 2: DATA TRANSFORMATION FOR EACH MODEL
================================================

MODEL 1: COLLABORATIVE FILTERING (User-User Similarity)
--------------------------------------------------------

INPUT TRANSFORMATION:
ratings.csv → User-Item Rating Matrix

Step 1: Create Pivot Table
   Before:                          After (User-Item Matrix):
   
   user_id | movie_id | rating      movie1  movie2  movie3  movie4  movie5
   --------|----------|------       ------ ------- ------- ------- -------
   user1   | movie1   | 5          user1    5       0       4       0       3
   user1   | movie3   | 4          user2    0       4       0       5       0
   user1   | movie5   | 3          user3    3       4       5       0       0
   user2   | movie2   | 4          user4    0       0       0       4       5
   user2   | movie4   | 5
   ...
   
   - Rows = Users
   - Columns = Movies  
   - Values = Ratings (0 if user hasn't rated that movie)
   - Shape: ~100k users × ~20k movies = HUGE MATRIX!

Step 2: Compute User-User Similarity Matrix
   Using Cosine Similarity between user rating vectors:
   
   Similarity(user1, user2) = cos(θ) between their rating vectors
   
   Result: 100k × 100k similarity matrix
   
   Example:
           user1   user2   user3   user4
   user1   1.00    0.23    0.87    0.12
   user2   0.23    1.00    0.45    0.76
   user3   0.87    0.45    1.00    0.34
   user4   0.12    0.76    0.34    1.00
   
   - Value close to 1.0 = very similar taste
   - 0.87 means user1 and user3 have very similar preferences!

Step 3: Generate Recommendations
   For target user:
   1. Find 50 most similar users (highest similarity scores)
   2. Get movies THEY rated 4+ stars
   3. Weight by similarity score
   4. Return top 20 movies (that target user hasn't seen)


MODEL 2: CONTENT-BASED (Genre Matching)
-----------------------------------------

INPUT TRANSFORMATION:
ratings.csv + movies.json + watches.csv → User Profiles + Movie Features

Step 1: Build User Profiles
   For each user, aggregate their highly-rated movies:
   
   user_id: 10
   Rated 4+ stars:
   - Die Hard (Action, Thriller) - rating 5
   - The Matrix (Action, Sci-Fi) - rating 5
   - Pulp Fiction (Crime, Drama) - rating 4
   
   Genre Preference Score:
   {
     "Action": 3.33 (appears in 2/3 movies, avg rating 5),
     "Thriller": 1.67,
     "Sci-Fi": 1.67,
     "Crime": 1.33,
     "Drama": 1.33
   }

Step 2: Build Movie Features
   For each movie:
   {
     "movie_id": "die+hard+1988",
     "genres": {"Action", "Thriller"},
     "popularity": 542 (times watched),
     "year": 1988,
     "age": 38 (2026 - 1988)
   }

Step 3: Score Movies for User
   For each candidate movie:
   
   score = genre_match * 0.6 + popularity * 0.25 + recency * 0.15
   
   Example for user 10 (likes Action):
   - "Die Hard 2" (Action, Thriller): 
     genre_match = 0.9 (strong Action/Thriller match)
     popularity = 0.3 (moderately popular)
     recency = 0.2 (old movie)
     → final_score = 0.9*0.6 + 0.3*0.25 + 0.2*0.15 = 0.645
   
   Return top 20 highest-scored movies


MODEL 3: COLD-START HANDLER
----------------------------

INPUT: User's self_description_likes text

Step 1: Parse Mentioned Movies
   Text: "I love Star Wars, The Matrix, and Harry Potter"
   
   Extraction process:
   1. Normalize all movie titles → lowercase, remove "the"
   2. Search for substrings in user's text
   3. Found: ["star+wars+1977", "the+matrix+1999", "harry+potter+...+2001"]

Step 2: Extract Genres
   star wars → Science Fiction, Adventure
   the matrix → Action, Science Fiction    
   harry potter → Fantasy, Adventure
   
   Preferred genres: {Science Fiction, Adventure, Action, Fantasy}

Step 3: Recommend by Genre
   1. Find all movies with these genres
   2. Sort by popularity
   3. Return top 20

================================================
PART 3: WHAT IS NDCG@20?
================================================

NDCG = Normalized Discounted Cumulative Gain at rank 20

Purpose: Measure recommendation quality (higher is better, max = 1.0)

Key Idea: Reward models that put RELEVANT items at the TOP of recommendations

Example Scenario:
-----------------
User 123 has rated these movies 4-5 stars (these are "relevant"):
- The Godfather
- Pulp Fiction  
- The Shawshank Redemption
- Goodfellas
- Fight Club

Our model recommends (Top 20):
Rank 1:  Some Random Movie      ← NOT relevant (0 points)
Rank 2:  The Godfather          ← RELEVANT! (lots of points)
Rank 3:  Another Random Movie   ← NOT relevant
Rank 4:  Pulp Fiction           ← RELEVANT!
Rank 5:  Random Movie
...
Rank 17: Fight Club             ← RELEVANT but ranked low (fewer points)

DCG Formula:
DCG = Σ (relevance / log2(position + 1))

For our example:
- The Godfather at rank 2: 1.0 / log2(3) = 1.0 / 1.58 = 0.63
- Pulp Fiction at rank 4: 1.0 / log2(5) = 1.0 / 2.32 = 0.43
- Fight Club at rank 17: 1.0 / log2(18) = 1.0 / 4.17 = 0.24
Total DCG = 0.63 + 0.43 + 0.24 = 1.30

IDCG (Ideal DCG if we ranked all relevant items at top):
- Position 1: 1.0 / log2(2) = 1.0
- Position 2: 1.0 / log2(3) = 0.63
- Position 3: 1.0 / log2(4) = 0.5
- Position 4: 1.0 / log2(5) = 0.43
- Position 5: 1.0 / log2(6) = 0.39
Total IDCG = 2.95

NDCG = DCG / IDCG = 1.30 / 2.95 = 0.44

Interpretation:
- NDCG = 1.0: Perfect! All relevant items at the top
- NDCG = 0.44: Decent! We got some relevant items but not optimally ranked
- NDCG = 0.0: Bad! No relevant items in our recommendations

================================================
PART 4: WHY IS COLLABORATIVE FILTERING GETTING 0.0?
================================================

PROBLEM DIAGNOSIS:
-----------------

Looking at evaluation results:
- CF Model: NDCG@20 = 0.0 (NO relevant recommendations at all!)
- Content-Based: NDCG@20 = 0.031 (some relevant recommendations)

This happens when the model returns:
1. Empty recommendations [], OR
2. Recommendations that DON'T match what the user actually liked

Most likely causes:

CAUSE 1: USER ID TYPE MISMATCH
------------------------------
ratings.csv has:    user_id = INTEGER (e.g., 70106)
Our code converts:  user_id → STRING (e.g., "70106")
Model predicts for: STRING user_id
But test evaluates: Might be passing wrong type

Check in evaluate_models.py line ~90:
```python
recommendations = model.predict(str(user_id), top_k=20)
```

The rating matrix uses the original integer user_ids as index!


CAUSE 2: RATING SCALE MISMATCH
-------------------------------
ratings.csv has ratings 1-10 (not 1-5!)
Our code checks for ratings >= 4.0 to find "highly rated"

But look at the data:
- rating = 9 → highly liked
- rating = 8 → highly liked  
- rating = 4 → borderline (40% rating!)

We should adjust threshold!


CAUSE 3: EMPTY PREDICTIONS
---------------------------
Collaborative Filtering returns [] when:
- User not in training data
- User has no similar users
- No similar users rated movies highly

Check: Are we using the SAME user IDs for training and prediction?


FIXES TO IMPLEMENT:
-------------------

FIX 1: Ensure consistent user_id types throughout pipeline
       Make sure ratings.csv user_ids match what model expects

FIX 2: Adjust "highly rated" threshold for 1-10 scale
       Change: rating >= 4.0 → rating >= 7.0 (70%+ is "liked")

FIX 3: Add debug logging to see what's actually being returned
